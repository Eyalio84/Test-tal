# Plan: Aria-as-Editor — Voice Site Editing with Live Preview + Undo/Redo
_Generated: 20260307_0432 | Scope: feature addition_

## Summary
Extend ARIA_FUNCTIONS so the site owner can edit their live site by voice from `/admin/editor`.
Edits write to a draft state in SiteContent; the owner sees changes in a full-page preview iframe
with a floating toolbar (Undo/Redo/History/Publish). `publish_changes` copies draft → live +
`revalidatePath('/')`. Mouse/touch click-to-edit is also supported alongside voice.

## Architectural Decisions (from interview)
- **Editor route:** `/admin/editor` — admin-only (ADMIN_EMAIL guard inherited from `app/admin/layout.tsx`)
- **Content model:** Key-value rows (`{ id: "hero_text", draft: "...", live: "..." }`) — mirrors AriaMemory pattern
- **Draft vs live:** Every Aria/mouse edit writes to `draft` field only. `publish_changes` copies `draft → live` + `revalidatePath('/')`. Public site reads `live` only.
- **Undo/redo:** Full-site JSON snapshots in `SiteSnapshot` table (max 10). Client holds undo/redo stacks in Zustand, populated on mount from DB. New edit → snapshot current draft → apply change → clear redo stack.
- **Destructive confirm:** UI modal + voice. `remove_section` / `reorder_section` trigger a pending-confirm state in Zustand; modal appears; Aria listens for "yes"/"no" voice or button click.
- **UI layout:** Full-page draft preview iframe at top. Floating top bar: [↩ Undo] [↪ Redo] [DRAFT MODE] [History ▾] [Publish ✓]. Aria orb bottom-right (familiar). Cmd+Z / Cmd+Y keyboard shortcuts also work.
- **Mouse/touch editing:** Click-to-edit overlay on preview sections — same content API endpoints, same draft → live flow.

---

## Gaps & Enhancements Incorporated
- SiteContent schema is too sparse — add `draft` + `live` columns (replace single `value`)
- Add `SiteSnapshot` table for full-site undo/redo snapshots (max 10, trimmed server-side)
- Editor ARIA_FUNCTIONS must run only in editor context — add `editorMode: boolean` to Zustand and gate editor functions
- Aria system prompt needs an editor-mode variant injected when on `/admin/editor`
- Public site components must be updated to read `SiteContent.live` (not `draft`)
- Rate limit editor writes (10/min per IP) — inherit from `lib/rateLimit.ts`
- `publish_changes` should require at least one draft change vs live to prevent no-op publishes
- Add `lastEditedAt` + `lastEditedBy` to SiteContent for audit trail

---

## Out of Scope
- Per-customer editors (Plan #2 is admin-only; per-customer editing is Plan #5–7)
- Image upload (set_hero_image with file upload) — deferred to Plan #6 Visual Editor
- Real-time collaboration / multi-user editing — not needed for single-owner MVP
- Section-level granular undo (per-field) — full-site snapshots are sufficient for 10-state history

## Implementation Tasks

### Task 1: Prisma Schema — Extend SiteContent + Add SiteSnapshot
- **What:** Modify `SiteContent` to have `draft String @default("")` and `live String @default("")` replacing the single `value`. Add `SiteSnapshot` model for undo/redo: `(id, contentJson String, createdAt DateTime)`. Also add optional `lastEditedBy String?` to SiteContent.
- **Files:** `prisma/schema.prisma` — modify SiteContent, add SiteSnapshot
- **After:** Run `npx prisma db push` to sync to Neon
- **Model hint:** haiku
- **Notes:**
  - Existing SiteContent rows have `value` — migration must handle renaming. Use `db push` (no migration file needed for dev). If rows exist, copy `value → live` and `value → draft` then drop `value`.
  - SiteSnapshot has no userId — it's a global snapshot of the whole site draft (single-owner admin tool for now)
  - Keep last 10 snapshots: enforced in the API route (delete oldest when count > 10 after insert)

```prisma
model SiteContent {
  id           String   @id
  draft        String   @default("")
  live         String   @default("")
  lastEditedBy String?
  updatedAt    DateTime @updatedAt
}

model SiteSnapshot {
  id          String   @id @default(cuid())
  contentJson String   // JSON.stringify({ hero_text: "...", color_primary: "...", ... })
  createdAt   DateTime @default(now())
}
```

### Task 2: Content API Routes
- **What:** Create three API route files:
  1. `app/api/content/route.ts` — GET (returns all SiteContent rows; `?view=draft` for admin, default = live) + PATCH (update one key's draft value, save snapshot, trim snapshots to 10)
  2. `app/api/content/publish/route.ts` — POST (admin only: copy all draft → live + `revalidatePath('/')`)
  3. `app/api/content/snapshot/route.ts` — GET (returns ordered snapshots for undo/redo history UI) + POST with `{ action: "undo" | "redo", snapshotId }` (restores that snapshot's contentJson as current draft values)
- **Files:** `app/api/content/route.ts`, `app/api/content/publish/route.ts`, `app/api/content/snapshot/route.ts`
- **Model hint:** haiku
- **Notes:**
  - Auth pattern: copy from `app/api/aria/memory/route.ts` — use `auth()` from `@/lib/auth`, check `session.user.email === process.env.ADMIN_EMAIL` for all write operations
  - Rate limit PATCH with `checkRateLimit(ip, "content-write", 10, 60)` using lib/rateLimit.ts (10/min)
  - GET `/api/content` with no auth returns `live` values (used by public site components)
  - GET `/api/content?view=draft` requires admin session, returns `draft` values (used by editor iframe)
  - Snapshot trim: after INSERT into SiteSnapshot, DELETE FROM SiteSnapshot WHERE id NOT IN (SELECT id FROM SiteSnapshot ORDER BY createdAt DESC LIMIT 10)
  - `revalidatePath('/')` call in publish route — also revalidate `/products`, `/collections`, `/about`

### Task 3: Extend ARIA_FUNCTIONS + executeCommand for Editor Mode
- **What:** Add 8 new function declarations to ARIA_FUNCTIONS in `hooks/useAriaLive.ts`. Add corresponding cases in `executeCommand`. Gate editor functions: only call them when `aria().editorMode === true`.
- **Files:** `hooks/useAriaLive.ts`
- **Model hint:** sonnet
- **Notes:**
  - New functions to add:
    - `set_hero_text(text: string)` — updates `hero_text` draft key
    - `set_hero_subtitle(text: string)` — updates `hero_subtitle` draft key
    - `set_color(target: "primary"|"secondary"|"accent"|"background", value: string)` — updates `color_{target}` draft key
    - `add_section(type: "features"|"testimonials"|"cta"|"gallery", position: "after_hero"|"before_footer"|number)` — adds section to `sections` draft key (JSON array)
    - `remove_section(sectionId: string)` — triggers pending confirm modal before calling API
    - `reorder_section(sectionId: string, direction: "up"|"down")` — triggers pending confirm modal
    - `publish_changes()` — calls `/api/content/publish`
    - `undo()` — dispatches UNDO command to Zustand
    - `redo()` — dispatches REDO command to Zustand
  - Editor functions return status string back to Gemini: `"hero_text updated to: '${truncated}'"` so Aria can confirm what was heard
  - `remove_section` and `reorder_section` should NOT call API immediately — instead dispatch `{ type: "PENDING_CONFIRM", action: {...} }` to Zustand and return `"Awaiting confirmation"` to Gemini
  - Add editor-mode system prompt injection in `ws.onopen`: if `aria().editorMode`, append editor instructions to system prompt
  - Editor system prompt addition: "You are now in EDITOR MODE. You can edit the site by voice. After each edit, confirm what you changed in one sentence. For destructive actions (remove/reorder sections), always ask for confirmation first."

- **Files:** `store/aria.ts` (extend) or `store/editor.ts` (new)
- **Model hint:** haiku
- **Notes:**

  - `pendingConfirm: { action: string; args: Record<string, unknown> } | null` — holds destructive action waiting for confirm
  - `undoStack: string[]` and `redoStack: string[]` — arrays of SiteSnapshot IDs (fetched from DB on editor mount)

  - AriaCommand union: add `| { type: "UNDO" } | { type: "REDO" } | { type: "PENDING_CONFIRM"; action: string; args: Record<string, unknown> }`

### Task 5: Editor Page UI — /admin/editor
- **What:** Create the Aria editor page with: (1) full-page preview iframe loading the site in draft mode, (2) floating top toolbar with Undo/Redo/History/Publish, (3) Aria orb (existing component), (4) ConfirmModal for destructive actions, (5) click-to-edit overlay on sections for mouse/touch editing.
- **Files:** `app/admin/editor/page.tsx`, `app/admin/editor/EditorClient.tsx`, `app/admin/editor/EditorToolbar.tsx`, `app/admin/editor/ConfirmModal.tsx`, `app/admin/editor/ClickToEdit.tsx`
- **Model hint:** sonnet
- **Notes:**
  - `page.tsx` is a server component: verify `session.user.email === ADMIN_EMAIL` server-side (redirect to /admin if not), then render `<EditorClient />`
  - `EditorClient.tsx` sets `editorMode = true` in Zustand on mount, cleans up on unmount
  - The iframe `src` should point to `/?view=draft` — a special query param the public site reads to serve draft content (or use a separate `/preview` route that reads draft)

  - **OR** even simpler for MVP: don't use iframe at all — render the site components directly in the editor page, passing `contentMode="draft"` as a prop. The editor page IS the preview. This avoids iframe cross-origin issues.
  - Toolbar keyboard shortcuts: `useEffect` with keydown listener for Cmd+Z → dispatch UNDO, Cmd+Y / Cmd+Shift+Z → dispatch REDO
  - History dropdown: shows last 5 snapshots with relative timestamps ("2m ago"), click to restore
  - Publish button: calls POST `/api/content/publish`, shows loading spinner, toast on success/fail
  - ConfirmModal: listens to `pendingConfirm` in Zustand; appears when non-null; has [Cancel] [Confirm] buttons; also listens for voice via a `useEffect` on Aria transcript ("yes" → confirm, "no" → cancel)
  - ClickToEdit: each editable section gets a hover outline + pencil icon; click opens an inline text input or color picker; onChange → PATCH `/api/content` for that key; same draft pipeline as voice edits
