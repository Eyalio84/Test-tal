◈ Overview

StoreKit is a voice-AI website builder platform. Merchants pick a theme, then talk to Aria — a live Gemini-powered AI — to edit every part of their store.

Themes
8
Image Slots
72
Aria Contexts
3
Subscription Tiers
4

What it is

Users log in with Google, get a Site record provisioned automatically, choose one of 8 store themes, and can edit all content by speaking to Aria (a persistent Gemini Live WebSocket connection). The platform handles payments via Stripe, image hosting via Cloudflare R2, and stores all content in Neon PostgreSQL.

The admin panel gives the store owner tools to: switch themes, edit content visually, upload product images, curate CDN images with AI, and manage their subscription. The Image Scout tool uses Pexels + Gemini to fill all 72 image slots across all 8 themes.

▶ Quick Start

From zero to running dev server in under 10 minutes.

1 — Clone and install

git clone <repo-url>
cd tal-boilerplate
npm install

2 — Configure environment

cp .env.example .env.local
# Edit .env.local — fill in every required variable (see Environment Variables section)

3 — Set up the database

# Push schema to Neon (or any PostgreSQL) and regenerate Prisma client
npx prisma db push

# Enable pgvector extension (required for Image Scout embeddings)
psql $DATABASE_URL -c "CREATE EXTENSION IF NOT EXISTS vector;"
psql $DATABASE_URL -c "ALTER TABLE \"CdnImage\" ADD COLUMN IF NOT EXISTS embedding vector(768);"

# Seed with sample products + component registry
npx prisma db seed

4 — Start dev server

npm run dev
# → http://localhost:3000

5 — Register Google OAuth redirect

In Google Cloud Console → OAuth 2.0 Client, add authorized redirect URI:

http://localhost:3000/api/auth/callback/google
Dev port note: The dev server runs on port 3000 (locked in package.json and next.config.ts). If you change the port, update your Google OAuth credentials and NEXT_PUBLIC_SITE_URL.

⬡ System Architecture

Next.js App Router with server components doing DB reads and client components managing interactive state via Zustand. Aria connects directly from the browser to Gemini Live over WebSocket.

Request flow example: "User buys a product"

  1. User clicks Add to Cart → Zustand cart.ts store updated client-side
  2. User goes to /checkout → POST /api/checkout with cart items
  3. Server creates Stripe Checkout Session with line items → returns sessionUrl
  4. Browser redirects to Stripe-hosted checkout page
  5. After payment → Stripe POSTs checkout.session.completed to /api/webhooks/stripe
  6. Webhook handler writes Order + OrderItem records in DB
  7. User redirected back to /checkout?success=true

Request flow example: "Aria edits hero text by voice"

  1. User taps Aria orb in FloatingDock → useAriaLive.ts opens WebSocket to Gemini
  2. buildAriaConfig(themeId) builds system prompt with current context + page
  3. User speaks: "Change the hero headline to 'Handcrafted with love'"
  4. Gemini responds with function call: update_site_content({ field: "hero.headline", value: "..." })
  5. AriaCommandDispatcher handles the function call → POST /api/content/update
  6. DB updated, page re-renders with new content

How theme switching works

  1. Admin visits /admin/themes, clicks a theme, triggers POST /api/theme/switch
  2. API writes SiteContent.live key "active_theme" = new themeId
  3. Root layout calls getActiveTheme() on every request → reads this key
  4. ThemeApplier injects CSS custom properties into <head> for that theme
  5. All fonts are pre-loaded in root layout; CSS variable --font-heading selects active font

Image resolution (static fallback → DB override)

Each theme has image URLs defined in themes/[id].ts. These are static fallbacks. When resolveTheme(themeId) is called server-side, it fetches all ThemeImage records for that theme and merges them over the static config. This means Image Scout uploads take effect immediately without code changes or rebuilds.

// lib/themeImages.ts
const base = THEMES[themeId]               // static TypeScript config
const overrides = await prisma.themeImage.findMany({ where: { themeId } })
const bySlot = new Map(overrides.map(r => [r.slot, r.url]))

return {
  ...base,
  hero: { ...base.hero, image: bySlot.get("hero") ?? base.hero.image },
  products: base.products.map(p => ({ ...p, image: bySlot.get(p.slug) ?? p.image }))
}

🔍 Image Scout

An admin-only curation tool that fills all 72 CDN image slots across 8 themes. Uses Pexels stock photos or Gemini-refined searches, compresses to WebP, and stores semantic embeddings for deduplication.

Workflow

  1. Navigate to /admin/image-scout
  2. Select theme (e.g. jewelry) and slot (e.g. hero)
  3. Choose source: Pexels (direct search) or Gemini (AI-refined query, then Pexels)
  4. Type a search prompt and press Enter → 12 results appear
  5. Accept or reject each image (with optional rejection reason)
  6. Click Upload — first accepted image is processed and stored
  7. Repeat for next slot using the → Next slot button

Upload pipeline

POST /api/admin/image-scout/upload
  1. Fetch image from URL
  2. compressImage(buffer, { width: 1600 }) → WebP
  3. PutObjectCommand → R2 key: "themes/{themeId}/{slot}.webp"
  4. Upsert ThemeImage (slot → R2 URL override)
  5. Upsert CdnImage  (catalog entry with prompt, source, pexelsId)
  6. storeEmbedding(cdnImageId, prompt, altText)  ← async, non-blocking

Semantic search + deduplication

Every uploaded image gets a 768-dim embedding from gemini-embedding-001 stored in the CdnImage.embedding pgvector column. Before each upload, checkDuplicate() runs a cosine distance query — if distance < 0.08 the image is flagged as a duplicate of something already in the CDN catalog.

-- Semantic search (cosine distance, ascending = most similar first)
SELECT id, r2Key, themeId, slot, prompt, altText,
       embedding <=> $1::vector AS distance
FROM "CdnImage"
WHERE embedding IS NOT NULL
ORDER BY distance ASC
LIMIT $2

⚠ Gotchas

The "if something is broken, check this first" section.

Auth / OAuth

OAuth redirect loop: caused by adding pages: { signIn: "/api/auth/signin" } to NextAuth config. This config key was removed and MUST NOT be re-added. If users get stuck in a signin loop, check lib/auth.config.ts.
Google OAuth not working locally: ensure http://localhost:3000/api/auth/callback/google is in your Google Console authorized redirect URIs.

Database

siteId constraint error: siteId on Product, SiteContent, and SiteSnapshot is nullable. Don't set a default string value — FK constraints prevent it.
Prisma client out of sync: if you see prisma.cdnImage does not exist or similar, run npx prisma generate to regenerate the client after schema changes.
