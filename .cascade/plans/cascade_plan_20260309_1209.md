## Summary

Build a database-backed component registry system that powers three integrated UIs: admin CRUD (`/admin/components`), public showcase (`/components`), and editor palette (in `/dashboard/editor`). Implement 30-50 atomic components with standard props interface. Integrate with Aria so it can read the registry and execute voice commands to insert/edit/remove components on the canvas. Architecture: hybrid static TS fallback + DB-backed registry, ensuring resilience and scalability.

**Why now:** P4 is foundational for visual editor (P6) and Aria-as-editor integration (P7). Registry system must be in place before building drag-to-place or voice editing workflows.

**Approach:** Scout revealed strong existing patterns (admin CRUD, R2 integration, Aria WebSocket). Reuse these patterns extensively. Build in phases: registry infrastructure → initial 30-50 components → UI layer → Aria integration.

## Out of Scope

- **Component variants with independent DB tracking** — variants managed within component's `propsSchema`, not separate DB records. Example: Button has `variant: "primary" | "secondary"` as a prop, not separate DB entries.
- **Visual component sandbox in admin CRUD** — upload form is text + image, not live preview of all variants. Can add after MVP.
- **Batch component import** — admin imports one-at-a-time via UI form. Batch JSON import deferred.
- **Component version management** — components have updatedAt timestamp, but no explicit versioning (v1.0, v1.1). Deferred.
- **Rate limiting on component API** — existing `/lib/rateLimit.ts` is in-memory. Use as-is. Upgrade to Upstash Redis in post-launch phase per CLAUDE.md.
- **Tier-based component access** — all users see all 30-50 components. Tier-gating deferred.
- **Canvas state persistence** — component instances on canvas are ephemeral during edit session. Persist via SiteSnapshot (existing mechanism for site content).

export async function GET(request: NextRequest) {
  try {
    const category = request.nextUrl.searchParams.get('category');
    const search = request.nextUrl.searchParams.get('search');

    let where: Prisma.ComponentWhereInput = { siteId: null }; // global only for MVP
    if (category) where.category = category;
    if (search) {
      where.OR = [
        { name: { contains: search, mode: 'insensitive' } },
        { description: { contains: search, mode: 'insensitive' } },
        { ariaName: { contains: search, mode: 'insensitive' } },
      ];

    return NextResponse.json(components);
  } catch (error) {
    return NextResponse.json({ error: 'Failed to fetch' }, { status: 500 });

}

**Files:**

- Create: `app/api/admin/components/[id]/route.ts`

**Model Hint:** haiku

**Notes:**
- POST: create new component, validate slug uniqueness (Prisma unique constraint handles)
- PATCH: update component (all fields optional except id)
- DELETE: remove component (no soft delete for MVP)
- All three require `session?.user?.email === ADMIN_EMAIL` check
- Use createComponentSchema.parse() for POST, updateComponentSchema (partial) for PATCH
- Return 403 if not admin, 400 if validation fails, 201 for create, 200 for update/delete

**Code outline:**
```typescript
// POST /api/admin/components
async function POST(request: NextRequest) {
  const session = await auth();
  if (session?.user?.email !== env.ADMIN_EMAIL) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 403 });
  }

  const body = await request.json();
  const validated = createComponentSchema.parse(body);

  try {
    const component = await db.component.create({ data: validated });
    return NextResponse.json(component, { status: 201 });
  } catch (error) {
    if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === 'P2002') {
      return NextResponse.json({ error: 'Slug already exists' }, { status: 409 });
    }
    return NextResponse.json({ error: 'Failed to create' }, { status: 500 });
  }
}
```

### Task 4.3: Create Canvas Store (Zustand) for Component Instances

**What:** Build `store/canvas.ts` — Zustand store to manage component instances on the canvas during edit session. Track inserted components, props, order.

**Files:**
- Create: `store/canvas.ts`

**Model Hint:** haiku

**Notes:**
- Store shape:
  ```typescript
  interface ComponentInstance {
    id: string; // unique ID for this instance
    slug: string; // component slug (e.g., "primary_button")
    props: Record<string, any>; // user-provided props
    position?: string; // optional position hint for layout
    parentId?: string; // optional nesting
  }

  type CanvasStore = {
    instances: ComponentInstance[];
    addComponent: (slug, props, position?) => void;
    updateComponent: (id, props) => void;
    removeComponent: (id) => void;
    reorderComponent: (id, newPosition) => void;
    clearCanvas: () => void;
  }
  ```

- `addComponent`: generates unique ID, validates slug, appends to instances array
- `updateComponent`: finds by ID, merges props delta
- `removeComponent`: filters out by ID
- Aria executeCommand dispatches to these actions
